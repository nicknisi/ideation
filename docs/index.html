The pitch · What's inside

Six things a spec template won't do for you

One command accepts your mess and walks it to reviewed, committed code. Every gate along the way requires evidence, not enthusiasm.

Five gates, zero vibes

Problem, goals, success criteria, scope, consistency. Each gate needs a concrete artifact — a pass/fail goal, an explicit boundary — before anything gets written.

An interview that pushes back

One question at a time, each with a recommended answer. It reads your codebase instead of asking you — and it will not tell you your idea is interesting.

Critics with OPINIONS

Four adversarial lenses — scope-creep, over-engineering, hidden-dependency, success-criteria — maul the draft plan while a fix is still a one-line edit.

A contract you can hold

Gate evidence, nested scope tiers, an interactive phase graph, the run model the engine will actually follow, copyable run commands, and a decision log so rejected approaches stay rejected.

Execution that reviews itself

Every phase runs scout → build → verify-review-fix before it may commit. Autopilot plans dependency waves and runs independent phases in parallel.

A loop that remembers

Finished runs propose learnings; you accept or dismiss. The next interview applies them out loud — last project's stumble becomes this project's first question.

The shape · The loop at a glance

Seven moves, and what stops each one

The steps are the easy part — every process has steps. What makes this one a process rather than a checklist is that each move can refuse to continue. Pick a move to see what it takes and what it emits, or throw the switch to see every refusal at once.Every move is below, with what it takes, what it emits, and what stops it.

01 Brain dump you talk, /ideation listens

takes
Whatever you actually have — a paragraph, a rant, three half-ideas that don't reconcile. No template and no form to fill in.
emits
A position. What's strong and what's weak, named before the first question — not a summary of what you just said.
refuses
/ideation:brainstorm is the door before this one, for deciding whether at all. It can conclude “no” or “not yet”, and it writes no files either way — enforced by leaving Write, Edit and Bash off its tool list, not promised in prose.

02 Interview one question at a time, each with a recommended answer

takes
The dump, plus your codebase — it reads the code instead of asking you about it.
emits
Five evidence gates, each backed by a concrete artifact, and contract-data.json once they all read ready.
refuses
A gate that can't be evidenced keeps the interview running. Generation starts when all five are ready — not before, and not because you're impatient.

03 Critics four adversarial lenses, dispatched in parallel

takes
The draft plan, before it renders — while a fix is still a one-line JSON edit rather than a regenerate loop.
emits
Findings at three severities — blocker, notable, nit — through scope-creep, over-engineering, hidden-dependency and success-criteria.
refuses
A blocker sends the plan back. If it exposes a genuine unknown rather than a fixable defect, the interview reopens on that gate. The critics can't edit anything themselves — read-only is enforced by their tool list.

04 Contract & the fork the only place a human has to act

takes
The critiqued plan, with every rejected alternative already recorded so it stays rejected.
emits
contract.html to decide on, contract.md and specs to execute against, and a run-mode verdict — walk away, watch it run, or just run the one spec.
refuses
You do. Nothing proceeds until you explicitly approve, and the scope tier you pick decides what reaches the specs at all. Everything outside it becomes a future consideration rather than quietly shipping.

05 Execution waves scout → build → review ⇄ fix → commit, per phase

takes
contract.md and the specs. Independent phases run as a wave; two phases naming the same file are serialised even inside one.
emits
One commit per phase, each naming its spec path so a resumed run skips it. Then verify.mjs runs the contract's own checks and prints VERIFY {slug}: commits=A/B pass=N fail=M judgment=K.
refuses
Five ways. A scout HOLD under --strict. A build that fails its validation. A reviewer that never returns a verdict. A review still FAIL on the third cycle — changes left unstaged, nothing committed. And a commit with no named file refuses rather than reaching for git add -A.

06 Learnings push, not poll — proposed when a run finishes

takes
What actually happened, read out of the run's own implementation notes rather than remembered.
emits
Candidate lessons, deduped against what's already recorded so the same stumble isn't filed twice.
refuses
Nothing is written without you. Every candidate passes accept / edit / dismiss first — a learning store nobody curates is just a log.

07 The next idea the return arrow, not a gate

takes
docs/ideation/learnings.md — committed and shared with the repo, so it's the team's memory rather than one machine's private state.
emits
The next interview, which applies them out loud: last project's stumble becomes this project's first question.
refuses
Nothing. This is the one move that can't stop you — it just points back at 02.

Planning artifacts are HTML — built for deciding. Specs are Markdown — built for executing. The routing between an express finish and full review is recommended after the interview, when the evidence to choose actually exists.

The story · An illustrated walkthrough

The Bookmark Garden

One made-up feature — a garden where your bookmarks grow when you read them and wilt when you don't — walked through the entire ideation loop: brain dump, interview, critics, the fork, execution in waves, and the lesson the next project inherits.

Plate I · The mess

It starts as a brain dump

No structure required. You talk, /ideation listens — then takes a position instead of applauding.

you, thinking out loud okay so hear me out — a bookmark garden. you save a link and that plants a seed, and when you actually go back and read the thing it grows, and if you never do it wilts. your garden ends up being really honest about your reading habits. maybe seasons?? also pruning, for the stuff you'll truthfully never read. and it should feel cozy, not like a productivity app yelling at you
intake · position taken

Strong: a clear core loop — save → revisit → grow. That's a real feature.

Weak: "seasons" is a vibe, not a scope. And "cozy" can't be checked pass/fail — yet.

› interviewing until all five gates are ready

The one door accepts the dump exactly as spoken, names what's strong and what's weak up front, and starts the evidence-gated interview.

Plate II · The interview

One question at a time, with a scoreboard

Every question arrives with a recommendation. Every answer moves the gates. No batching, no question limit, no "that's an interesting approach."

Q2Is pruning deletion, or archiving? I'd recommend archiving — gardeners compost, they don't incinerate.
youarchive. nothing is ever really gone.

Q3Direct questions aren't converging here. Here's a strawman of my current best guess — want to react to it instead?
React to this strawman — say what to keep, change, or kill; the reaction becomes the gate's evidence
Keep asking questions
Flag the gate and move on
strawman · wilting, v0 — wrong on purpose unvisited 30 days → leaves droop · 60 days → stem browns · 90 days → auto-composts into the archive
"no — more like this: droop all you want, but NOTHING auto-composts. I decide what leaves the garden."

› reaction folded into Success Criteria as evidence. The strawman is disposable; the reaction isn't.

Gates: 5/5 ready

The scoreboard prints after every answer. When a gate stalls on wording, the interview sketches a strawman to react to — one minute of "no, more like this" beats a fourth direct question.

Plate III · The critics

The critics have OPINIONS

Before the contract renders, four adversarial lenses descend on the draft in parallel — while a fix is still a one-line JSON edit, not a regenerate loop.

critic digest · shown at the approval gate

scope-creep found 1 (1 blocker folded in)

over-engineering found 1 (1 blocker folded in)

hidden-dependency found 1 (1 blocker folded in)

success-criteria found 1 (1 notable — "cozy" tagged judgment call)

Critics run once per contract, in parallel. Blockers are folded in before the contract ever renders, and every fold-in lands in the decision log so the "why" survives.

Plate IV · The fork

One question routes the finish

The contract is generated and opened. Now the flow's centerpiece: approval and routing, asked together — with the recommendation's reasoning in plain sight.

approval & routing · one AskUserQuestion, two questions

› Routing recommendation — express: all 5 gates went ready without an early stop, and 4 of 6 success criteria carry check commands.

1 · Which scope tier should we target?

Full — build MVP + Full tiers
MVP — ship the minimum viable version first
Stretch — include the seasons, apparently

2 · Approve the contract — and how should we finish?

Approve — express finish — specs generate with no further approval questions and execute immediately on an isolation branch
Approve — full review — interactive review continues: spec approval, then the handoff menu
Needs changes — some parts need revision before approving

Approval and routing are one consolidated question. Express deletes the remaining ceremony, never the artifacts — and it's only recommended when the interview's evidence earns it. An early-stopped interview doesn't even get the option.

Plate V · Execution

Phases commit in waves

Specs are generated (self-review hard-gated), and autopilot takes the isolation branch. Independent phases run in parallel; anything sharing a file is serialized. Every phase earns its commit.

Each phase runs scout → build → verify-review-fix (three cycles max) before it may commit. Express runs are strict: a crashed reviewer stops the run — unreviewed code never lands silently.

Plate VI · The harvest

The run ends. The filter asks once.

The finished run's implementation notes pass through the generalization filter. Trivia composts; patterns that would change the next spec survive. Two candidates made it.

completion

Branch: ideation/bookmark-garden

Review: git diff main...ideation/bookmark-garden

learning capture · one question, accept/edit/dismiss

Keep any of these for future interviews? (multi-select · "Other" edits the wording)

docs/ideation/learnings.md ## 2026-07-23 — bookmark-garden
- Pattern: Specs that schedule time-based behavior never said which process observes the clock.
  Evidence: Phase 2 wilt-timer gap decision
  Spec/interview implication: When a feature depends on elapsed time, ask "where does the clock live?" before phasing.

› zero candidates would have meant zero prompts — a clean run stays silent.

Capture is push-based and human-gated: at most three candidates, one accept/edit/dismiss question, nothing auto-appended. Unattended runs never write this file — their notes wait for the next interactive intake.
