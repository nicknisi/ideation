lint-prompts — corpus scope and the italic-anchor near-miss rule

Context
The spec scoped v1 to paths, § anchors, and frontmatter, and said tune patterns until the live corpus is clean, never the other way around. Two judgment calls remained: how wide the corpus walks, and how to check italic anchors (*When to stop*) without flagging emphasis italics (*The decision*) — templates and prose both use single-asterisk spans heavily.
Decision
Corpus = the 17 markdown files under skills/ + references/ (the spec's minimum; agents/*.md and workflows/README.md not widened in — v1 stays where the check surface was verified). Italic anchors: a span exactly matching a corpus heading is a reference (checked, passes); a span matching only after case/whitespace normalization is flagged as a suspected rename-left-behind; anything else is emphasis and skipped. This catches the common rot (heading reworded by case or a word swapped) with zero false positives on the live tree, and cannot catch a wholesale rename — a documented limit, accepted per the machine-shaped-only rule. Bare numeric references without § (express's "4.2's phasing") stay unchecked for the same reason.
Alternative
Flagging every unmatched italic span (hundreds of false positives — emphasis is idiomatic in this corpus), and hardcoding an emphasis allowlist (a second prose owner — the failure mode the spec names). Both rejected.

Scenario evals — transcripts + manual checklist shipped; automation rejected

Context
The spec pre-authorized the fallback: "if the harness can't produce a trustworthy assertion, ship the transcripts + checklist and stop." The three invariants (scoreboard each turn, contract refused before gates close, spike on the unanswerable but not the testable) assert model behavior, and this build stage cannot dispatch a live interview to observe it anyway.
Decision
Shipped test-fixtures/evals/ (tracked, matching the fixture convention: README + content): three transcripts (messy dump, settled decision, scope-creeper) with per-turn scripted probes and assertions, plus a README that documents the replay procedure and records why automation was rejected — a scripted driver can feed turns but its assertions would be a second model grading the first, and grep-level assertions false-pass on quotes and false-fail on paraphrases. The settled-decision transcript carries both spike legs; the other two carry the premature-contract probe.
Alternative
A subagent-driven harness with mechanical assertions (grep for scoreboard shape, grep for spike offer). Rejected: the spike offer's wording is prose, and the assertion that matters ("offered here, withheld there") needs a reader — forcing it would be the spec's named failure mode, not a win.

Pre-existing test-environment bug fixed: verify.test.mjs inherited global commit signing

Context
The phase opened with a red baseline: scripts/verify.test.mjs's commit-matching tests failed (and hung ~60s each) because repoWithCommitFor builds a throwaway repo that inherits the user's global commit.gpgsign=true, and this machine's SSH signer (1Password op-ssh-sign) is unavailable to headless processes — the commit silently never lands, so the test fails for the wrong reason after the signer's timeout.
Decision
Added git('config', 'commit.gpgsign', 'false') to the fixture with a comment naming why. A unit test's throwaway repo must not depend on the user's global git config — the same principle the test file already states for repo history. Baseline is now 162 → 170 green in ~0.8s. Out of the spec's File Changes table but required to reach a green baseline; flagged here per the spec-gap rule.
Alternative
Running validation with a GIT_CONFIG_* environment override and leaving the test unchanged. Rejected: the failure is real on any contributor machine with signing enabled and an unavailable signer — hiding it in this session leaves it for the next one.
