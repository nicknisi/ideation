The problem

01The plugin's entry surface forces the ceremony decision before the information exists: users choose /ideation:ideation vs /ideation:express before the interview, yet the interview is identical in both and gate confidence plus criteria verifiability — the exact inputs for that choice — only exist after it. Six user-facing skills compound the surface-area problem.

02The contract exists in three representations, one of them hand-authored: contract-data.json renders contract.html mechanically, but contract.md is hand-mirrored by the model, inviting drift, and the express skill needs ordering rules just to keep re-runs archiving cleanly. The plugin's own over-engineering critic flagged the unread third copy.

03The interview gives no progress feedback — one-question-per-turn is correct elicitation, but the user cannot see how many gates remain, making interviews feel unbounded. The express confirmation has the opposite problem: a wall of terminal text (a 12-row criteria table plus tiers plus digest) duplicating what the rendered contract already shows.

04The learning loop is structurally dead: /ideation:retro is pull-based (must be remembered at the moment of least motivation), empty-input-prone (clean runs produce nothing, training users it is pointless), and silently consumed (intake reads learnings.md invisibly). Field evidence is decisive — every adopted mechanism (Devin knowledge suggestions, Windsurf memories, Claude Code auto-memory) moved capture off the user, and Cursor removed its approval-gated Memories feature entirely. learnings.md has never been created in this repo.

Goals ×5
01 /ideation is the single default front door: identical interview, then a post-interview routing recommendation (express-style single confirmation vs full interactive review) derived from gate evidence and criteria verifiability; /ideation:express survives as a pre-commit alias that skips the routing question.
02 contract.md becomes generator output: contract-gen.ts renders it from contract-data.json alongside contract.html, preserving the exact structure autopilot's fallback parser and get-goal-prompt consume; neither skill hand-mirrors it again.
03 The interview shows a one-line gate scoreboard after each answer (e.g. 'Gates: 3/5 ready — open: criteria, scope'), inherited by both skills from the shared engine.
04 The express-style confirmation is a terminal summary (criteria counts, top checks, one line per critic lens) with full detail living in the rendered contract.
05 The learning loop goes push-based: interactive completions propose up to 3 candidate learnings with one accept/edit/dismiss question, intake visibly attributes any learning it applies and surfaces unmined implementation notes from prior unattended runs, and /ideation:retro is deleted with all references updated.

Decisions considered and rejected ×15
  • Absorb retro into completion capture and intake attribution, then delete the command— rejected: Dropping the learning loop entirely, or keeping /ideation:retro as-is. Field evidence shows pull-based retro ceremonies are never used (Cursor removed its equivalent; every adopted mechanism is push-based), but retro's generalization filter and dedupe/retire discipline are sound — only the trigger and visibility are broken.
  • Keep /ideation:express as a pre-commit alias over the shared flow— rejected: Deleting the express command for a single-command surface. Zero migration cost, preserves the ability to commit to walk-away mode upfront, and /ideation still becomes the default door.
  • Move the ceremony choice to a post-interview routing recommendation— rejected: Keeping the pre-interview ideation-vs-express fork. Gate confidence and criteria verifiability are the routing inputs and they only exist after the interview; both skills already share the identical interview.
  • contract.md becomes generator output from contract-data.json— rejected: Continuing to hand-mirror contract.md from the template. Hand-mirroring is drift-prone (flagged by the plugin's own over-engineering critic); a generated md turns parser compatibility into a testable output contract.
  • In the /ideation path the clean-tree check runs at routing time, not before the interview— rejected: Running the express Phase 0 tree check before every /ideation interview. A clean tree is only needed if the user routes to immediate isolated execution, which is unknown pre-interview; the cost is one stash prompt after routing.
  • Unattended runs never auto-capture learnings; the next interactive intake surfaces unmined notes— rejected: Auto-appending unreviewed learnings from headless completions. Silent file writes erode trust and violate the accept/edit/dismiss contract; push-at-next-touch keeps capture human-approved without resurrecting a dead command.
  • Express-style confirmation becomes a terminal summary with detail in the rendered contract— rejected: Keeping the full criteria table and digest inline in the terminal. The 12-row wall duplicates the artifact the flow just rendered; the gate stays informed via counts, top checks, and one line per critic lens.
  • Express alias is a thin pointer (~10-20 lines) into /ideation's routing path, which solely owns express semantics— rejected: Keeping express as a parallel skill file overriding ideation sections by reference. Over-engineering critic: the parallel file's only remaining function post-routing is pre-answering one question, while its section-reference coupling taxes every future ideation edit — the same coupling that required hard constraints twice in one day.
  • The generalization/dedupe/retire filter is written once in a shared reference and invoked at completion (bounded to the just-finished project) and intake (bounded unmined-notes scan)— rejected: Duplicating the filter logic inside execute-spec, autopilot, and the interview engine. Three hot-path copies of mining logic would drift; one reference, two invocation points keeps the discipline testable and the intake scan cost bounded.
  • Zero qualifying candidates at completion produces no prompt and no output— rejected: Always showing the capture question after interactive runs. A mandatory prompt on clean runs recreates exactly the empty-input fatigue the problem statement condemns in retro.
  • The retro-reference sweep includes both .claude-plugin manifest descriptions— rejected: Sweeping only skills/, references/, and README. Success-criteria critic blocker: plugin.json and marketplace.json both advertise /ideation:retro; without them in scope the plugin ships describing a command it no longer has while the check passes green.
  • The full learnings.md lifecycle (bootstrap, entry format, dedupe amendments, retirement) relocates wholesale to the shared reference— rejected: Relocating only the generalization filter and leaving lifecycle rules to die with the retro command. Hidden-dependency critic blocker: retro is the sole producer of learnings.md and intake is a format-dependent consumer; partial relocation lets the file rot with duplicates and stale entries — the exact decay retro existed to prevent.
  • Generated contract.md keeps full parser-compatible structure as a deliberate legacy compatibility contract— rejected: A minimal human-readable md, since the fallback parser never fires for generator-produced projects (contract-data.json always exists). The structure is free at render time, keeps pre-JSON projects and the json-deleted recovery path working, and one smoke criterion is cheap; the live roles (locator, human record) get it for free.
  • Lineage archiving treats generator-emitted html+md as a pair archived together— rejected: Keeping the sibling-md mtime heuristic unchanged. The heuristic exists because hand-authored md was written after the html; when one invocation emits both, mtimes are near-equal and the comparison is meaningless — the archive step must handle the pair explicitly.
  • The workflow example becomes a self-contained animated HTML page replacing references/workflow-example.md— rejected: Rewriting the markdown walkthrough in place. User direction at contract approval: the walkthrough is human-facing and no skill instruction reads the md file, so the rendered treatment costs nothing downstream; resource lists must drop the dangling md reference.
