buildMarkdown — judgment-call criterion rendering

Context
The spec's key decision reads: success criteria render as - [ ] {criterion} — check: `{check}` or — judgment call: {criterion} when no check. The second fragment is ambiguous — read literally it would place the criterion text after the marker, producing a checklist line that starts with an em-dash.
Decision
Render - [ ] {criterion} — judgment call: criterion first, marker as suffix. Every existing representation puts the criterion first — the HTML renderer (criterion, then a "judgment call — no mechanical check" tag) and both hand-authored canon contracts (… — judgment call: {what a human looks at}). The mechanical renderer has no separate "what a human looks at" field, so the suffix carries no colon clause.
Alternative
The literal reading, - [ ] — judgment call: {criterion} — rejected because it breaks the criterion-first ordering every other renderer and canon file uses, and reads as a malformed checklist item.

buildMarkdown — numbered-step titles are not de-duplicated

Context
Execution steps render as {n}. **Phase {n}** — {title} (the canon shape). The orchestration fixture's titles already embed "Phase N — …", so its generated steps read "**Phase 1** — Phase 1 — root", where the hand-authored canon wrote "**Phase 1** — root".
Decision
Keep the mechanical rendering. Titles are data; the graph annotations and (blocked by {title}) references use full titles verbatim, and the fallback parser matches on titles — silently rewriting them risks breaking that correspondence for a purely cosmetic gain on one synthetic fixture.
Alternative
Stripping a redundant Phase {n} [—:] prefix from titles at render time — rejected as improvisation beyond the spec ("follow spec literally"), with drift risk between the rendered label and the title autopilot matches against.

Skill edits — express Phase 3 cross-reference retarget

Context
The spec scopes the express edit to "generator invocation lines only: Phase 5 steps 3–4 collapse into one invocation". Collapsing them renumbers the render step from 4 to 3, and express Phase 3's intro cites it by number: "rendering moves to Phase 5 step 4".
Decision
Updated that one citation to "Phase 5 step 3". Leaving a dangling step number is the exact failure mode the spec's own risk table flags for the ideation file (broken section citations); the fix is one token and keeps the file internally consistent until Phase 2 rewrites it wholesale.
Alternative
Strictly touching invocation lines only and leaving the stale "step 4" reference — rejected: it would point at a step that no longer exists.
